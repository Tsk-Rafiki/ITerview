# ITerview

## База данных

Приложение использует локальную **SQLite/Room** базу данных. В ней хранятся весь контент, включая Markdown-теорию, состояние пользователя и метаданные импорта. Серверная база данных и синхронизация аккаунта в текущую задачу не входят.

Контент создается и редактируется отдельным веб-редактором, который формирует полный JSON-снимок. Мобильный importer проверяет JSON во временной staging-БД и атомарно обновляет текущий контент. Избранное, прогресс и история ответов при этом не изменяются. Отсутствующие в новом снимке сущности деактивируются, а не удаляются физически, чтобы сохранить связи с локальным состоянием.

### Структура и ответственность таблиц

#### Контент

| Таблица | Зона ответственности |
|---|---|
| `technology` | Справочник технологий: Kotlin, Android и последующие. Хранит название и признак активности. |
| `section` | Разделы внутри технологии и их порядок отображения. Группирует связанные темы. |
| `topic` | Темы обучения, их порядок, Markdown-теория и принадлежность разделу технологии. |
| `topic_tag` | Теги тем для поиска, фильтрации и группировки. Одна строка связывает один тег с одной темой. |
| `puzzle` | Паззлеры: вопрос, фрагмент кода, сложность, объяснение и правильный вариант. `topic_id = NULL` обозначает задачу всей технологии, заполненный `topic_id` — задачу темы. |
| `puzzle_option` | Варианты ответов и порядок их отображения. Стабильный `option_id` позволяет менять порядок вариантов без изменения правильного ответа и истории. |

#### Локальное состояние пользователя

Эти таблицы не входят в контентный JSON и не изменяются при импорте контента.

| Таблица | Зона ответственности |
|---|---|
| `topic_favorite` | Отметки избранных тем. Наличие строки означает, что тема добавлена в избранное. |
| `topic_progress` | Прогресс изучения темы: признак прочтения теории и время прочтения. |
| `puzzle_result` | Сводный результат по каждой задаче: последний выбранный ответ, правильность, число попыток и время последней попытки. |
| `puzzle_answer` | Неизменяемая история ответов пользователя с выбранным вариантом, результатом и версией контента на момент ответа. |

#### Метаданные контента и импорта

| Таблица | Зона ответственности |
|---|---|
| `content_bundle` | Принятые полные JSON-снимки, их версии, хеши и источники. Используется для проверки повторного импорта, аудита и отката контента. |
| `mobile_content_state` | Единственная запись с указателем на активную версию контента. Переключается в той же транзакции, что и текущий контент. |
| `import_candidate` | Состояние проверяемого или загружаемого снимка: версия, хеш, статус, ошибка и расположение временной staging-БД. Помогает восстановиться после прерванного импорта. |

### Идентификаторы и основные связи

- `technology_id` уникален в пределах всей мобильной БД.
- Темы и паззлеры идентифицируются составными ключами `(technology_id, topic_id)` и `(technology_id, puzzle_id)`.
- Варианты ответов идентифицируются ключом `(technology_id, puzzle_id, option_id)`.
- Контентные идентификаторы имеют тип `TEXT` и приходят из JSON. Они стабильны: изменение названия, теории или порядка не должно менять ID.
- Версии контента, порядок отображения, счетчики попыток и timestamps хранятся как `INTEGER`.
- Выборка задач по технологии объединяет прямые задачи технологии и задачи всех ее тем без копирования записей.
